API keys
Adds passive subdomains (dns/domain) plus per-IP open ports, org/ISP, ASN and known CVEs. Get a key at account.shodan.io.
Free for researchers — adds per-IP indexed services and any exposed-data leaks LeakIX has found for that host. Register and grab a key under Settings → API key at leakix.net (free account required — LeakIX doesn't offer a keyless tier the way Shodan's InternetDB below does).
Only used if whatweb has already detected WordPress on a host — wpscan will not run otherwise. Register a free key at wpscan.com. Worth knowing: the free tier is a strict 25 requests/day, and WPScan spends roughly one request per installed plugin/theme it checks — a single scan of a plugin-heavy site can exhaust the whole daily quota on its own. This app only scans one WordPress-confirmed host per run (not every one found) to help stay within that.
Runs during the Company scan — real, verified emails found for the domain (not guessed from a name pattern), plus the organization's detected address format. A sharper source than CrossLinked (which finds employee names, not addresses, by default) or theHarvester (search-engine scraping, which can surface a third-party ISP/MSSP's address instead of the actual company's). Register a free key at hunter.io — 50 lookups/month, no card required.
Shodan InternetDB needs no key or account at all — it's always on if enabled below, and runs alongside (not instead of) the full Shodan integration above if you have a key for that too. It only returns a lighter subset (open ports, hostnames, CPEs, tags, known CVEs — no org/ISP/banners), refreshed weekly rather than in real time, but costs nothing to use.
AI analysis — entirely optional
Adds a narrative analysis layer to the Company profile — a threat-modeling write-up generated by an LLM, reasoning over this scan's own already-collected findings. Nothing else in this app depends on this in any way; every feature works identically whether or not it's configured. Works with any OpenAI-compatible chat-completions endpoint — a locally-running Ollama server (nothing leaves your machine), or a cloud provider like Groq or OpenRouter.
Built-in tools & sources
crtsh, ip-geo and social-scan need no API key or installed binary — they're free HTTP lookups (certificate transparency, ip-api.com geolocation, and a homepage scrape for social links/meta tags). whois, theharvester, naabu and nmap need those binaries on PATH. nmap runs a quick top-100-port pass in Fast mode and a deeper top-1000 pass with version detection and default scripts in Full mode — both use -Pn so hosts that don't respond to ping still get scanned rather than skipped. The exact command each one runs is shown under its name — handy as a reference when you're writing your own below.
Custom CLI tools
Run as shell command
Enables &&, ;, |, redirection — lets you chain multiple tools into one entry
Use {domain} as a placeholder. In plain mode it's substituted directly into the argument list, not through a shell, so there's no quoting/injection concern — but that also means one binary, no chaining. Runs as a subdomain-discovery step in both scan modes; results are tagged with the tool's name as the source.
Example combining two tools into one entry:
subfinder -d {domain} -silent && assetfinder --subs-only {domain}
Both commands' output is captured and merged. {domain} is shell-quoted automatically before substitution, and the domain itself is validated server-side to reject shell metacharacters — so this is safe to use even though a shell is involved.
Custom API resources
Placeholders: {domain} always available; {ip} available for enrichment sources whose URL includes it (called once per resolved IP instead of once per domain); {api_key} filled from the key field above. For a subdomain source, the JSON path should point at a list — either of plain hostname strings, or of objects, in which case add |fieldname to pull the hostname out of each object (e.g. data.results|hostname). For an enrichment source, each comma-separated field path is looked up in the response and stored as intel against the host/IP.
Wordlists
Upload wordlist files here once, then assign one to amass, dnsx, ffuf, or shuffledns from that tool's own entry in the Tools sidebar (or the Vulnerability module's tool list, for ffuf). Once assigned, that tool's command changes itself automatically on the next scan — but the effect is genuinely different depending on the tool: amass/dnsx run fine either way, a wordlist just adds a bruteforce pass on top of what they'd already do passively, while ffuf/ shuffledns have nothing to do at all without one and are skipped outright until you assign a wordlist.
Backup & restore
Everything — every scan, every log, every custom tool/variant/API source/key — already persists automatically in surface.db next to app.py. It survives restarts on its own; nothing here is required for normal day-to-day use. This is for moving that state around: back it up before wiping a machine, copy it to a new install, or restore an earlier snapshot.
⬇ Download backup
Restoring replaces everything currently in the app — all scans, tools, variants, and keys — with whatever's in the uploaded file. There's no undo short of restoring a different backup, so make sure that's really what you want first.
Clear cached / stored data
Two different things live here, worth telling apart. The app now tells your browser never to cache any of its pages going forward, but that doesn't retroactively clear whatever it already cached from before this fix existed — Clear browser cache below does that. Separately, Reset scan data wipes the app's own stored results (every scan, host, port, etc.) while leaving your setup — custom tools, bespoke command variants, API keys — untouched.
